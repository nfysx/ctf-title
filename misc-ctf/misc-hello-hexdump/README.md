# 题解：把文件当字节看

> 对应第三课 p27 十六进制视角 · p34 二进制格式

## 一、题目与考点

| 项 | 值 |
|---|---|
| 考点 | `xxd` / `hexdump -C`、字节视角、分隔符 |
| 难度 | 1 |
| 分值 | 80 |
| 附件 | `files/blob.bin`（61 字节） |
| Flag 格式 | `flag{...}` |

引入题。题意只有一句：文件里写着 flag，但 `strings` 一条都捞不到。要换的不是工具，是视角：不把文件当文本，而当一串字节。

## 题面（直接复制到平台「简介」）

`files/blob.bin` 是一个 61 字节的小文件，`strings` 对它什么也不输出，作者把写进去的字符拆开了，中间还塞了别的东西。目标：按字节把被打散的内容拼回来。

**提示**：文本工具按「连续可打印」算一段，插入一个字节就能让它断开。

## 三、解题步骤

### Step 1｜认类型

```bash
file blob.bin
```

```
blob.bin: data
```

### Step 2｜换成十六进制视角

```bash
xxd blob.bin
```

```
00000000: a55a 0100 2d00 0000 0200 0000 666c 0061  .Z..-.......fl.a
00000010: 6700 7b68 0065 7800 5f69 0073 5f00 6a75  g.{h.ex._i.s_.ju
00000020: 0073 7400 5f61 006e 6f00 7468 0065 7200  .st._a.no.th.er.
00000030: 5f76 0069 6500 777d 00de adbe ef         _v.ie.w}.....
```

怎么读：最左是行首偏移；中间每两个十六进制字符是一个字节；最右是这些字节的 ASCII 渲染，不可打印的显示成 `.`。

于是头 12 字节一眼就懂：`a5 5a` 是魔数，`01` 版本、`00` 保留，`2d 00 00 00` 是 45（正文长度），`02 00 00 00` 是 2（每组字节数）。**每组 2 字节后面那个 `00`，就是 `strings` 抓不到的原因**。

Linux / macOS 上的等价命令是 `hexdump -C blob.bin`，结构一样：偏移 + 16 字节十六进制 + ASCII 列，只是十六进制按 8 字节分两段显示。

Windows 上没有 `xxd` 时，用 coreutils 的 `od`：

```bash
od -A x -t x1z blob.bin
```

```
000000 a5 5a 01 00 2d 00 00 00 02 00 00 00 66 6c 00 61  >.Z..-.......fl.a<
000010 67 00 7b 68 00 65 78 00 5f 69 00 73 5f 00 6a 75  >g.{h.ex._i.s_.ju<
000020 00 73 74 00 5f 61 00 6e 6f 00 74 68 00 65 72 00  >.st._a.no.th.er.<
000030 5f 76 00 69 65 00 77 7d 00 de ad be ef           >_v.ie.w}.....<
00003d
```

或者 PowerShell 的 `Format-Hex blob.bin`。

### Step 3｜确认 `strings` 为什么抓不到

```bash
strings blob.bin
```

```
（没有任何输出）
```

把阈值降到 3 一样是空的：每段可打印字节只有 2 个。

### Step 4｜把散落的字节拼回来

先让 `strings` 把阈值降到 2，逐组吐出来：

```bash
strings -n 2 blob.bin
```

```
fl
ag
{h
ex
_i
s_
ju
st
_a
no
th
er
_v
ie
w}
```

再把这些行首尾接起来（`tr -d '\n'` 删掉换行）：

```bash
strings -n 2 blob.bin | tr -d '\n'
```

```
flag{..........}
```

Windows 上没有 `tr` 的话：

```powershell
-join (strings -n 2 blob.bin)
```

不想用管道也行：照着 Step 2 的十六进制输出，每 3 个字节里取前 2 个、跳过 `00`，手工抄一遍，结果一样。

### Step 5｜自己动手

`flag{..........}` 那一行跑出来就是完整答案。把它填进平台。

## 四、原理

- 文本工具只认「可打印字符的连续段」。插入一个不可打印字节，段的长度立刻掉到阈值以下，`strings` 不是看不见内容，是规则让它不打印。
- 十六进制视图不丢信息。任何字节都能读出来，包括分隔符本身；而分隔符的**位置**（每 2 字节后出现一个 `00`）反过来暴露了分组规则。这也解释了为什么本题的文件头要写「每组 2 字节」：它把规则写在了文件里。
- 「文本」和「字节」是两个层次的东西。同一个文件，用 `strings` 看是一堆碎片，用 `xxd` 看是完整有序的数据。题目难不难，往往取决于你站在哪一层看。

## 五、防御建议

- 用「插分隔符」「切成碎片」当保护，等于没有保护：字节就在文件里，任何十六进制编辑器都能读。要保密就用加密（AES + 密钥管理），或者干脆不把数据放进去。
- 反过来，做检测时可以拿这个特征当线索：新出现的、结构异常规整的二进制片段（定长分组、固定分隔符、固定间隔的同一个字节）值得单独看一眼，正常编码不会留着这么多规律。
- 交付前用两条命令各过一遍：`strings -n 4` 看可打印内容、`xxd | head` 看头部结构，比只看其中一个靠谱。
