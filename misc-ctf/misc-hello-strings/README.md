# 题解：字符串就在文件里

> 对应第三课 p27 十六进制视角 · p31 信息泄露

## 一、题目与考点

| 项 | 值 |
|---|---|
| 考点 | `file` 判类型、`strings` 捞可打印串、`grep` 过滤 |
| 难度 | 1 |
| 分值 | 80 |
| 附件 | `files/notice.bin`（193 字节） |
| Flag 格式 | `flag{...}` |

引入题。不考编码、不考隐写，只练一条链路：类型看字节 → 文本用 `strings` 捞 → 用 `grep` 过滤。

## 题面（直接复制到平台「简介」）

值班表上留了一个 `files/notice.bin`：没有扩展名，双击打不开，记事本里是一屏乱码。它其实是一份社团通知，正文前面套了几字节的容器头。目标：把通知里要提交的那串东西取出来。

**提示**：二进制文件里的可打印字符，是可以被整体捞出来的。

## 三、解题步骤

### Step 1｜认类型

```bash
file notice.bin
```

```
notice.bin: data
```

`data` 的意思是「不属于已知的文本 / 图片 / 压缩包」。到这一步别再靠后缀猜，直接看字节。

Windows 上常常没有 `file`，那就读头部 16 字节：

```bash
python -c "print(open('notice.bin','rb').read()[:16])"
```

```
b'NOTI\xb9\x00\x00\x00NOTICE 2'
```

`NOTI` 就是魔数，紧跟的 `b9 00 00 00` 是小端的 185，正好等于文件长度 193 减去 8 字节头。

### Step 2｜捞可打印串

`strings` 只有一条规则：连续 ≥4 个可打印 ASCII 字节，算一条字符串。它不看编码，也不管文件是什么格式。

```bash
strings notice.bin
```

```
NOTI
NOTICE 2026-11-03
 19:00
 B203
flag{..........}
```

中文整段不见了：UTF-8 的每个汉字都是 ≥`0x80` 的字节，不在可打印 ASCII 范围内，`strings` 直接跳过。留下来的都是 ASCII，flag 就在里面。

（`NOTI` 是容器头的魔数；` 19:00`、` B203` 前面那个空格是正文里真实存在的 `0x20`，夹在中文和数字之间，`strings` 只是照抄。）

### Step 3｜过滤

```bash
strings notice.bin | grep flag
```

```
flag{..........}
```

只想看长一点的串，可以把阈值调高，让 4 字节的 `NOTI`、`B203` 也消失：

```bash
strings -n 6 notice.bin
```

Windows 没有 `grep` 时：

```powershell
strings notice.bin | Select-String flag
```

### Step 4｜自己动手

上面两处写着 `flag{..........}` 的地方，跑一遍就是完整答案。把那一行原样填进平台。

## 四、原理

- 文件类型由字节决定。`file` 读的是文件头里的魔数和结构，扩展名只是名字，改后缀不改变文件是什么。
- `strings` 是「字节流的可打印段提取器」：遍历每个字节，连续可打印的攒成一条，遇到不可打印就切断。它不需要知道格式，所以对任何二进制都有效。
- 中文被过滤不是巧合：UTF-8 用多字节表示非 ASCII，每个字节的高位都是 1。这让「ASCII 文本」和「其他内容」在字节层面天然分开了，本题正好借它把干扰降为零。

## 五、防御建议

- 密钥、口令、内部地址、调试凭据不要写进二进制或随附件分发。`strings` 一条命令就能捞出来，不需要任何逆向。
- 发布前把产物扫一遍：`strings 产物 | grep -iE 'pass|secret|token|key'`，命中就回看这条数据该不该在这里。
- 删掉日志里的那条记录不够。同一份数据常常还留在备份、崩溃转储、构建缓存、以及自定义文件头里。本题的容器头就是一个例子：它不藏东西，但它把「正文有多长」明明白白写在开头。
