# 题解：没有密码的加密包

> 对应第三课 p33 伪加密

## 一、题目与考点

| 项 | 值 |
|---|---|
| 考点 | 伪加密、ZIP 结构、标志位 |
| 难度 | 2 / 3 |
| 分值 | 150 |
| 附件 | 见下 |
| Flag | 静态（`flag{...}`），checker 见 `checker/main.rx` |

解压时提示要密码，其实根本没有密码 —— ZIP 头里的加密标志位被置上了。

### 附件

| 文件 | 说明 |
|---|---|
| `files/secret.zip` | 附件 |

## 二、手把手解题

### Step 1｜先确认「要密码」

```bash
unzip files/secret.zip
# → [secret.zip] flag.txt Password:
```


### Step 2｜看字节

```bash
xxd files/secret.zip | head -3
```

本地文件头里有一个 2 字节的「通用标志位」（偏移 6），bit0 = 1 表示「已加密」。
真正的加密包，这个位置上还会有一大段加密数据；而这里除了标志位，别的都是明文 —— 所以是**伪加密**。

**注意**：中央目录（`PK\x01\x02`，偏移 +8）里也有一份同样的标志位，要多数工具看的是那一份。

### Step 3｜清掉标志位

`verify.py` 里给了完整代码：把本地头和中央目录两处 bit0 都清掉，另存一份（写到系统临时目录）。

### Step 4｜解压拿 flag

```bash
unzip _fixed.zip && cat flag.txt
```


## 三、为什么能成（原理）

ZIP 是「本地头 + 中央目录」双份元数据。很多工具只读其中一份判断是否加密，
把标志位置 1 就足以让工具弹密码框，而实际数据压根没加密 —— 这就是伪加密。

## 四、怎么防（延伸）

不要把「文件加密」当成安全保证：真正的机密必须用标准加密（AES-256 的 7z / age / GPG），
而不是靠 ZIP 的加密位。收到可疑压缩包时，也不要相信「要密码」这个提示。

## 五、平台接入（ret2shell）

- `checker/main.rx` 是可直接用的静态 flag 版本：`check()` 比对答案，`environ()` 返回空对象
- 想改成**动态附件评测**：用平台自带的 `mapped` 预设替换这个文件，
  由平台把附件按用户映射并注入每用户唯一的 flag，本文件的 `check` 逻辑就不再需要
