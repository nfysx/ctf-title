## 二、手把手解题

### Step 1｜别双击，先看字节

```bash
xxd files/作业.docx | head -2
```

```
00000000: 504b 0304 1400 0000 0800 ...   PK..
```

`50 4B 03 04` 就是 ZIP 的签名。

### Step 2｜改后缀

把 `.docx` 改成 `.zip`，双击就能看到里面的 `flag.txt`。

### Step 3｜Windows 里的小技巧

如果看不后缀：资源管理器 → 查看 → 勾上「文件扩展名」。


## 三、为什么能成（原理）

**文件类型由内容决定，不由后缀决定**。Word 的 .docx 本质就是个 zip（装着 XML）。
所以「改后缀」这一步在真机上一样成立：服务端如果只看后缀就放行，那就等着出事。

## 四、怎么防（延伸）

上传接口必须按**内容**判类型（读魔数），不能信 Content-Type 和后缀。

## 五、平台接入（ret2shell）

- `checker/main.rx` 是可直接用的静态 flag 版本：`check()` 比对答案，`environ()` 返回空对象
- 想改成**动态附件评测**：用平台自带的 `mapped` 预设替换这个文件，
  由平台把附件按用户映射并注入每用户唯一的 flag，本文件的 `check` 逻辑就不再需要
- 附件型题目不需要容器镜像，直接把 `files/` 挂到题目附件上就行
