## 二、手把手解题

### Step 1｜看开头

```bash
xxd files/logo.png | head -2
```

看到：
```
00000000: 0000 0000 0d0a 1a0a 0000 000d 4948 4452  ............IHDR
```

开头是 4 个 `00`，但紧跟着 `0d 0a 1a 0a` —— 这是 PNG 签名 `89 50 4E 47 0D 0A 1A 0A` 的**后半段**。
后面还能看到 `IHDR` 块，进一步确认是 PNG。

### Step 2｜补回文件头

PNG 签名前 4 字节是 `89 50 4E 47`（`\x89PNG`）。用 Python 补回去：

```python
data = open('files/logo.png','rb').read()
open('fixed.png','wb').write(b'\x89PNG' + data[4:])
```

`verify.py` 里就是这段代码（它把修复结果写到系统临时目录，不污染题目目录）。

### Step 3｜看图拿 flag

打开 `_fixed.png` —— 一张真实的长城照片，底部说明条上就是 flag。


## 三、为什么能成（原理）

文件类型由**字节**决定，不由后缀决定；而文件头（魔数）是程序判断类型的依据。
所以「抹掉文件头」不等于「换了个文件」—— 只要剩下的结构还在，补回签名就能还原。

## 四、怎么防（延伸）

上传文件的服务端必须**按内容判断类型**（`finfo_file` / 读魔数），而不是信任后缀或 Content-Type。
这也是第二课上传题的同一条原则：客户端说的一切都要验证。

## 五、平台接入（ret2shell）

- `checker/main.rx` 是可直接用的静态 flag 版本：`check()` 比对答案，`environ()` 返回空对象
- 想改成**动态附件评测**：用平台自带的 `mapped` 预设替换这个文件，
  由平台把附件按用户映射并注入每用户唯一的 flag，本文件的 `check` 逻辑就不再需要
- 附件型题目不需要容器镜像，直接把 `files/` 挂到题目附件上就行
