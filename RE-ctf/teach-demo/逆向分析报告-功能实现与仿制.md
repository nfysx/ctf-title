## 0. 一句话结论

这不是一个"逆向挑战题"，而是一个**用 .NET 8 WPF 写的"逆向教学陪练"程序**：它把教学内容做成 JSON "课程脚本"，运行时**站在旁边看着你用 DIE / IDA / x64dbg / Ghidra / dnSpy**，通过 Win32 窗口枚举 + UI Automation 文本树判断"你现在到了哪一步"，然后在一个**覆盖全屏、置顶、点击穿透的透明窗**上贴高亮框和气泡，并自动把你的进度推进到对应的步骤。整个过程**不注入、不 Hook、不读对方进程内存**。

| 维度 | 结论 |
| --- | --- |
| 文件形态 | .NET 8 **框架依赖单文件**（framework-dependent single-file），外壳是官方 apphost，载荷是 2.5 MB 托管 DLL |
| 技术栈 | WPF（`Microsoft.WindowsDesktop.App`）+ 纯 BCL，**无任何第三方 NuGet** |
| 代码规模 | 93 个 .cs、约 58 万字节反编译源码；最大单文件 MainWindow.cs 108KB |
| 数据形态 | 一份 1.7 MB 内嵌 ZIP（30 个文件）在首次启动时解到 **exe 同级目录** |
| 核心价值点 | Guide 引擎（窗口/控件识别 + 打分 + 悬浮层）与内容契约（课程/关卡/引导脚本） |
| 仿制难度 | 外壳与内容层 3 天可复刻；Guide 引擎要 2～3 周才能到"不误跳步"的水准 |

### 4.4 `stages/*.json`（真正的"教学脚本"）

顶层（对齐 `schemas/guide-stage.schema.json`，210 行、`additionalProperties:false`）：

```json
{ "id":"chall1.die", "order":0,
  "titleKey":"chall1.die.title", "goalKey":"chall1.die.goal",
  "answerKey":"chall1.answer.external_submit_only",

  "fakeAnswerKeys":[],                   // 假 flag（诱导"猜答案"）
```

**step 是内容作者唯一要写的东西**，也是仿制时最需要保真的结构：

```json
{ "id":"read_die_result", "textKey":"...", "bodyKey":"...", "image":"courses/chall1/assets/media/01-die-analysis.png",
  "action":"none", "tool":"die", "file":"chall1",
  "guide": {
    "target": { "scope":"process", "process":"tool:die", "adapter":"die", "titleContains":["Detect It Easy"] },
    "locators": [
      { "strategy":"uia", "scope":"process", "process":"tool:die", "adapter":"die",
        "role":"analysis_summary", "titleContains":["Detect It Easy"], "documentContains":["chall1"],
        "contentContains":["ELF64","AMD64","C/C++"], "requireAllNameContains":true,
        "contentMode":"evidence", "fallbackToWindow":false, "maxNodes":1800, "timeoutMs":800 },
      { "strategy":"window", "scope":"process", "process":"tool:die", "adapter":"die",
        "titleContains":["Detect It Easy"], "fallbackToWindow":true, "timeoutMs":500 }
    ],
    "overlay": { "placement":"right","alignment":"center","padding":8,"gap":16,"maxWidth":460 },
    "fallback": { "scope":"host","key":"coach" }
  },
  "trigger": { "kind":"locator_found", "locator": { ...同上第一条 locator... } }
}
```

**为什么设计成"定位器数组 + trigger"**：同一段讲解要能适配不同分辨率/不同工具版本。locator 按顺序尝试，命中"精确"就停；trigger 用同一套证据反向判断"用户是不是已经做到了这一步"，从而**自动前进**。

### 4.5 `guide` 的完整字段族（照抄即可兼容）

| 结构 | 关键字段（小驼峰，全部 `[JsonPropertyName]`） |
| --- | --- |
| `target` / `fallback` | `scope`(host/process/screen/none)、`key`、`process`(`tool:ida`/`target:chall1`)、`adapter`、`titleContains`、`processNameContains`、`exeNameContains`、`exePathContains`、`windowClassNameContains`、`titlePidFromProcess` |
| `locator` | 上面全部 + `strategy`(auto/host/uia/win32/window/process_window/rect/none)、`state`、`role`、`nameEquals`、`nameContains`、`contentContains`、`documentContains`、`contentMode`(evidence/target)、`rejectTitleContains`、`rejectContentContains`、`requireAllNameContains`、`automationId`、`className`、`controlType`、`rect`、`adjust`、`fallbackToWindow`、`maxNodes`(50~10000)、`timeoutMs`(100~10000) |
| `overlay` | `placement`(auto/top/bottom/left/right/inside)、`alignment`(start/center/end)、`padding`(6)、`gap`(14)、`offsetX/Y`、`maxWidth` |
| `condition` | `kind`(always/all/any/process_running/window_visible/locator_found/host_visible/value_equals/value_contains)、`not`、`process`、`key`、`value`/`valueKey`、`locator`、`all[]`、`any[]` |
| `branch` | `trigger`("next"/"action"/"any")、`when`(condition)、`next`(step id) |
| `deviation` | `id`、`textKey`、`bodyKey`、`image`、`priority`、`when`、`guide` |

序列化约定：只设 `PropertyNameCaseInsensitive = true`，**没有**命名策略、不做 schema 校验（多余字段被静默忽略）；默认值靠 C# 属性初始化器。

### 4.6 进度与需求

`config/progress.json`（**PascalCase**，读取时用默认 options → 区分大小写，手改 camelCase 会被静默丢弃）：

```json
{ "ActiveCourseId":"chall1",
  "Courses": { "chall1": { "CourseVersion":"1.0.2", "FlowFingerprint":"<sha256 hex>",
                           "StageId":"chall1.die", "StageIndex":0, "ClearedStages":["chall1.die"] } },
  "StageIndex":0, "ClearedStages":["chall1.die"] }
```

**两个必须记住的不变量**：
1. 进度身份 = `(CourseVersion, FlowFingerprint)`，任一变化 → 该课进度**清零**；
   `FlowFingerprint = SHA256( 依次 lower(filename)+\0+文件字节+\0 )`。
2. 已通关关卡不回退：`Math.Max(存档 StageIndex, MinimumActiveStageIndexFromClearedProgress())`。

`config/requirements.json`（**小驼峰**，与 progress.json 风格相反）：

```json
{ "tools": { "ida": "C:\\Tools\\IDA\\ida64.exe" },
  "courseTargets": { "chall1": { "target.chall1": "...\\courses\\chall1\\assets\\targets\\chall1" } },
  "courseChoices": { "chall1": { "...": "..." } } }
```

需求匹配顺序：`fileNames 通配 → pathContains(all) → size → sha256`，**四项全过**才算命中。

### 4.7 内容包的安装语义（一个容易踩的坑）

`BundledContentInstaller` 对 zip 里每个文件算 SHA-256，与 `config/bundled-content-state.json`（30 条"相对路径→大写 SHA256"）比对：

- 磁盘 hash == 包内 hash → 已最新，跳过；
- 磁盘 hash == 上次安装记录的 hash（说明用户没改过）→ 覆盖；
- 其它（用户改过 / state 里没有记录）→ **continue，永不覆盖**。

→ 好处：用户手改的文案不会被回滚；坏处：**新版内置内容可能不生效**，只能手删目录。

## 5. 运行流程

### 5.1 启动序列（App.cs:17-53 → MainWindow.cs:312-385）

```
App.Main → App.OnStartup
 ├ 分支 A: --apply-update <request.json>   程序自更新的"第二进程"，装完 Shutdown(0/1)
 ├ 分支 B: --bootstrap-only                只安装内容 + 校验三个关键文件存在（CI 用，exit 2 = 内容不就绪）
 └ 正式启动
    ├ HostUpdateInstaller.CleanupCompletedUpdates()   清理 *.completed.json / *.download / apply-*
    └ new MainWindow()      ← 字段初始化器先跑：new PathService() → BundledContentInstaller.Install()
       ├ InitializeComponent()（加载 mainwindow.baml）
       ├ NativeWindowChromeService.Attach(this, 12.0)   DWM 圆角 + WM_GETMINMAXINFO 钳制
       ├ new GuideRuntime(...) / GuideTrackingCoordinator(...)
       ├ 200ms DispatcherTimer（追踪）+ 1s Timer（任务栏时钟）
       ├ ApplyStaticTexts() → RebuildCourseHub() → LoadStage() → ShowHub()
       └ Loaded → FitWindowToWorkArea() → CheckForUpdatesAsync(automatic:true)
```

没有单实例锁、没有全局异常处理、没有 App.xaml.cs 的额外逻辑（就 100 行）。

### 5.2 Hub ⇄ Desk 状态机

```
ShowDesk() 四重门禁：
  ① 课程已加载  ② IsHostCompatible（[min, max) 区间）  ③ 需求全部满足  ④ → 进入 Desk

NextStep（MainWindow:2054-2101）：
  if (!_guideUnlocked) → 解锁引导，停在第一步
  if (分支命中 "next") → 跳到分支目标 step
  if (还有下一步) → step++
  else if (completionMode != "answer") → 记通关，进下一关
  else → step = Steps.Count（引导走完），等提交 flag
```

**两条互不相干的判定链**（这是最容易搞错的地方）：

| 问题 | 判定方式 | 落盘 |
| --- | --- | --- |
| 能不能进课程？ | requirements：target/tool 的 sha256/size/文件名 + 工具路径 | `requirements.json` |
| 这一关过没过？ | `completionMode`：answer→比对 `answerKey` 文案；external_submit→靠识别到"工具里已完成"；其它→走到末步即过 | `progress.json` 的 `ClearedStages` |

提交时还有一层反作弊：命中的若是 `fakeAnswerKeys` 里的值，会提示"这个看起来像 flag，但它出现在错误路径附近"（原文见 zh-CN.json 的 `common.fake_flag`）。

### 5.3 识别 → 自动推进（"用户乱点也不会卡住"）

```
200ms tick → StartTrackingScanIfIdle（单飞门闩 Interlocked）
   ├ StartOverlay:  Task.Run(GuideRuntime.LocateExternalOverlayAsync(minScore 30))
   └ StartRecognition: 节流 240ms → RecognizeCourse(minScore 140)
        → RecognitionStabilizer.Observe( 同一 (revision,stage,step,pid,hwnd) 连续 2 次才放行, 1400ms 过期 )
        → Dispatcher.BeginInvoke(Background) → 校验 result.Revision == _guideRevision
        → TrySyncDetectedScene：只前进不后退，补记跨过的关卡为 cleared，Save()
```

关键常数（**决定"会不会乱跳步"，复刻时要么照抄要么整体重标定**）：

| 常数 | 值 | 作用 |
| --- | --- | --- |
| 识别阈值 | 140 | trigger 命中场景的 Score 门槛 |
| 置信度 | `35·App + 30·State + 25·Doc (+10 precise)`，< 65 丢弃 | 认不出来就什么都不做 |
| 证据强度 | `1000·App + 400·Doc + 120·State` | 多候选排序 |
| 歧义判定 | 领先 ≥60 或 specificity 差 ≥36 才算赢；精确目标领先 <25 视为歧义 | 宁可不说 |
| 窗口快照 TTL | 120 ms | 一次渲染内复用 EnumWindows |
| UIA 缓存 | 450 ms，节点 ≤3000，耗时 ≤1200 ms | 单次扫描预算 |
| 进程刷新 | 300 ms | 新开的 IDA 能被发现 |
| 稳定器 | 2 次 / 1400 ms | 刚创建的 Qt 窗口树是半成品 |

## 6. Guide 引擎（核心，值得单独看）

### 6.1 它怎么"看"别人的窗口

```
EnumWindows（过滤 IsWindowVisible + 标题非空 + 宽高 ≥50）
  ├ 矩形: DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS=9) 失败才退回 GetWindowRect
  │        → 否则 Win11 阴影会让高亮框"大一圈"
  ├ 客户区: GetClientRect + ClientToScreen（归一化坐标的参考系）
  ├ 归属: GetWindow(GW_OWNER) / GetAncestor(GA_ROOTOWNER) / GetLastActivePopup
  └ 进程: NtQueryInformationProcess(ProcessBasicInformation) 取父 PID 做 BFS
           → 才能接上 Ghidra 的 ghidraRun.bat → javaw → java
```

### 6.2 控件级定位（"先适配器知识，再通用 UIA，最后整窗兜底"）

```
1) Adapter 知识库命中（IDA 13 个界面状态 / x64dbg / Ghidra / DIE / dnSpy）
2) 反证：rejectContentContains 命中 → 立刻判"不是这个界面"
3) 内容证据：控制树里必须同时出现 contentContains/documentContains 全部关键词
4) 通用控件匹配：Name/Value/Text/自动化 ID/类名/控件类型打分
5) 只有内容证据、没有控件锚点 → 整窗 + "已验证区域"
6) fallbackToWindow 才允许退化成整窗
```

UIA 侧工程要点（照抄能省两周）：

- 用 `TreeWalker.ControlViewWalker` 而非 RawView（Qt/Java 的 RawView 节点会爆炸）；
- **快照 + BFS**：一次遍历 3000 节点/1200 ms，多个 locator 复用；按 hwnd 缓存 450 ms，带修订号防旧树覆盖；
- `SemaphoreSlim(clamp(CPU/2, 2, 6))` 全局并发闸，`Wait(0)` **抢不到直接判超时**（绝不排队，否则 200 ms 节拍会雪崩）；
- 超时后对该窗口退避 5 s，只走 Win32 枚举；
- 文本逐级升级：`Name → ValuePattern → LegacyIAccessiblePattern(LookupById(10018)) → TextPattern.GetText(800)`
  （Legacy pattern 是 IDA 自绘控件、Qt 控件的**唯一**文本通道；TextPattern 才能看到伪代码里的字符串）；
- 快路径：对 ≤8 条 ≤128 字符的 hint 用 `OrCondition(NameProperty, ValuePattern.ValueProperty)` 让 UIA 引擎内部一次匹配，把"遍历 3000 节点"降级成"一次比较"。

### 6.3 三套坐标系（最容易翻车的地方）

| 名称 | 产生处 | 用途 |
| --- | --- | --- |
| screen（物理像素） | 所有最终 `BoundsScreen` | Win32/UIA 返回的都是物理像素 |
| window/client 归一化（0..1） | `LocatedRect.FromWindow` | 适配器固定百分比区域、分辨率无关重投影 |
| host（DIP） | 主窗口内嵌引导层 | 画在自己窗口里 |

物理像素 → WPF DIP 一律用 `CompositionTarget.TransformFromDevice`，**不要**手算 96/dpi（PerMonitorV2 多屏不同缩放必错）。

### 6.4 HUD 窗口（点击穿透是"四件套"）

```csharp
// XAML: WindowStyle=None, AllowsTransparency=True, Topmost=True,
//       ShowInTaskbar=False, ShowActivated=False, ResizeMode=NoResize
ShowActivated = false; Focusable = false; IsHitTestVisible = false;
Left/Top/Width/Height = SystemParameters.VirtualScreen*   // 覆盖整个虚拟桌面（多屏）
// 代码补充 exstyle：
WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_LAYERED
```

| 手段 | 少了会怎样 |
| --- | --- |
| `WS_EX_TRANSPARENT` + `IsHitTestVisible=false` | 全屏透明窗挡住整个桌面，程序直接不可用（**最致命**） |
| `WS_EX_NOACTIVATE` + `ShowActivated=false` | 每次刷新都把焦点从 IDA 抢走，用户没法打字 |
| `Topmost` | 目标窗口一激活就盖住气泡 |
| `WS_EX_TOOLWINDOW` | 任务栏/Alt-Tab 多一个空白窗 |
| 覆盖 `VirtualScreen` | 目标在副屏时气泡画在屏外 |

气泡摆放：`auto` 按 **右 → 下 → 上 → 左 → 内** 找第一个放得下的方向（下方/上方要求 ≥116+gap），再用目标所在显示器 `rcWork` 做 clamp（`MonitorFromRect` + `GetMonitorInfo`），所以多屏不会跑到另一块屏上。每个 `ShowGuide` 都重设一次窗口尺寸与 exstyle（显示器热插拔后系统会重置）。

### 6.5 适配器知识库（"为什么能认出 IDA 的伪代码窗口"）

每个 Adapter = 一个身份签名（进程/可执行/标题/类名）+ 一组 `States`（界面状态→判定条件）+ 一组 `Roles`（语义角色→定位方式 + 固定百分比兜底区域）。

IDA 的 13 个状态：`quick_start / open_file_modal / load_file / database_exists_modal / database_repair_modal / problem_modal / debug_info_modal / analysis_modal / main / strings / xrefs / disassembly / pseudocode`。

例：区分"打开文件框"和"加载文件(Load a new file)框"——两者标题都可能含 Open，只能靠 `rejectContentContains`（`DWARF debug information`、`Import file names/line numbers`）+ `MinContentMatches ≥2`。

### 7.4 必须保留的契约（改了就不兼容内容）

1. 目录布局与 `DataRoot = exe 同级 \MoeCTF.RE.Tutorial`；
2. 所有内容 JSON 的**字段名逐字**（camelCase）与默认值；
3. scope 归一化：`child/external/target → process`、`desktop → host`；
4. 渲染计划的四态门槛：`Layer ∈ {none,host,screen}`，只有 `{window, verified-region, control, content}` 可显示；
5. 证据字符串词法（`managed-pid:` `reject-content:` `ambiguous-window-candidates:` …）——大量判定是对前缀做 `StartsWith`，改词法会让语义门槛静默失效；
6. 进程键约定 `tool:<id>` / `target:<文件名>`；
7. 进度身份 `(CourseVersion, FlowFingerprint)` 与指纹算法；
8. 阈值常数（140 / 65 / 60 / 36 / 25）。

### 7.5 可以简化（不影响内容）

- Adapter 的 13 个 IDA 状态：只保留当前课程用到的（chall1 只用 `die` + `ida` 的 `strings/xrefs/disassembly/pseudocode`）；
- Win32 子窗回退后端（UIA 够用时不必写）；
- `RecognitionStabilizer` 的 2 次可降为 1 次 + 重试（代价是偶发误跳）；
- `BoundsInWindow` 归一化链路（原程序里**只写不读**）；
- 内容/程序双更新链路（自建分发时可退化为"下载 + SHA256 校验 + 手动重开"）。

### 7.6 十四个坑（挑最痛的）

1. **UIA 会被对端拖死**：目标 UI 线程忙时读 `node.Current` 可能阻塞数百 ms～数秒 → 必须"后台 + 非阻塞抢闸 + 超时丢弃"。
2. **UI Automation 有 UIPI 限制**：目标以管理员运行时，非提权的仿制程序拿到的树是**空的且不报错**。
3. **DPI**：UIA 给物理像素、WPF 用 DIP，必须 `TransformFromDevice`；不能用 `PrimaryScreenWidth` 这类单屏假设。
4. **HWND 会复用**：显示前必须按 `(Hwnd, Pid)` 双键复核窗口仍在。
5. **点击穿透四件套缺一不可**（见 6.4）。
6. **`SetForegroundWindow` 有前台锁**：每步只抢一次，且要接受失败。
7. **单文件资源要先落盘**：i18n/课程 JSON 是高频小文件读取，且内容更新需要可写目录。
8. **模态框归属**：只按 PID 找窗口会把"IDA 主窗 + 模态框"当成两个候选，必须用 `LastActivePopup/RootOwner` 加权（原程序模态 +140）。
9. **固定百分比兜底区域很脆**：面板一拖就偏，是"演示能过"的手段。
10. **缓存键要含全部输入**：浮点用 `0.###` 定点格式，否则键抖动命中率崩。
11. **EnumWindows 的 ≥50px 过滤**会漏掉无标题浮层，放宽又会引入歧义。
12. **双语 hint**：所有关键词都写了中英两版（`内存布局`/`Memory Map`），不要"本地化"掉一侧。
13. **`Program Files` 下不可写**：安装/进度/更新会连环失败。
14. **`step.image` 是相对 ContentRoot 的完整路径**（`courses/chall1/assets/media/x.png`），不是相对 `assetsDir`。

1. **仿制的目标粒度**：现在给的是"能跑通内容 + 定位 + 自动推进"的骨架（13 个 .cs、约 2000 行）。你要的是
   ① 继续补到**功能对齐原版**（加 Adapter 知识库、需求门禁、内容更新），还是
   ② 只要**最小可用**（能读课程、能贴提示），还是
   ③ 只要设计文档不要代码？—— 我按 ①-半成品 交付了，后续方向等你定。
2. **题目附件 `chall1` 的哈希对不上**：本地 `D:\ctf\RE-ctf\teach-demo\chall1` 的 SHA-256 是
   `ea730409f02618d07c163551c10f3a6313fd3509cf64e9090dc78ae2c4b825d1`，而 `course.json` 声明
   `f86808dd1c38a0b64b843b2f4cdb57d49b688c20c8e6a5ccdf3e08e7e931fa44`（size 16,120 一致）。
   哪个是正确附件？这直接影响"需求门禁能否通过"的复刻验证。
3. **是否要保留原版的目录契约**（`exe 同级 \MoeCTF.RE.Tutorial`，需要写权限）？还是改成 `%LOCALAPPDATA%`（会更稳，但别人的 `progress.json` 不能直接搬）。
4. **是否需要"识别即通关"的判定**（原程序 `completionMode=external_submit` 时会不经用户确认就把关卡记为 cleared）？这是个体验/正确性取舍，我不想替你决定。
5. **教学对象**：仿制版是给"和你一样的逆向学习者"用（那就要 Adapter 知识库做到 IDA 版本兼容），还是给"教学方做新课程"用（那重点是内容作者体验 + schema 校验工具）？
6. **要不要一并逆向课程里的 `chall1`**（Linux ELF，涉及 `Input flag:` / `strncmp(s, s2, 0x3A)` / `loc_401270` 那条校验链）？它和宿主程序是两回事，我可以单独出一份。
