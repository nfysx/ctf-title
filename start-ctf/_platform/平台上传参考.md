## 平台怎么"收题"：两件事，不是一件事

| 东西 | 放在哪 | 怎么进去 |
|---|---|---|
| **容器镜像** | 平台自带的私有 registry（NodePort 30310，仅集群内部可达） | `POST /api/game/4/registry`，multipart 字段名 `file`，服务端用 `skopeo copy` 入库 |
| **题目定义** | 游戏的 git 题库仓库（bucket） | 后台表单写入，或 `git push` → post-receive 钩子同步进 DB |

镜像仓库名 = **tar 文件名去掉扩展名**（`connect-ctf.tar` → `connect-ctf`），
标签 = **上传时刻的 Unix 时间戳**（服务端生成，不是你给的）。

所以「上传」= 传 tar + 建题，两步。

├── config.toml              # 题名「连接平台」、标签 Misc/Web、50 分固定

├── 题面.md                   # 题面（后台「简介」tab）
├── hints.toml               # 免费提示 1 条
├── answer.md                # 题解（归档后可展示）

所以每支队伍拿到的 flag 都不同，且 flag 里隐写了队伍 id——别人把 flag 给你，平台会记一条作弊审计。

## 路线 A：后台点选（推荐）

### A1. 拿 token

平台所有 `/api` 接口都要 `Authorization: Bearer <token>`。三种拿法：

- **浏览器 DevTools**：登录后随便点个接口，复制请求头里的 `Authorization`（最快）
- **登录接口**：
  ```bash
  curl -s -X POST http://10.24.10.232/api/account/login \
    -H "Content-Type: application/json" \
    -d '{"account":"<账号>","password":"<密码>","captcha_id":"<id>","captcha_answer":"<答案>"}' \
    -D - -o /dev/null | grep -i "^set-token"
  ```
  （登录要验证码，验证码接口是 `/api/account/captcha`）
- **官方 CLI**：`r2s auth login` 会把 token 存到 `%APPDATA%\ret2shell\client.toml`

### A2. 传镜像

```powershell
cd D:\ctf\start-ctf\connect-ctf
pwsh ./upload-image.ps1 -Token <token>
```

脚本做的事（每一步都可单独手动跑）：

1. `GET /api/game/4` 取 bucket，`GET /api/game/4/registry/config` 取 `external`
2. `docker build -t connect-ctf-web:latest ..`
3. `docker save` → `connect-ctf.tar`
4. `POST /api/game/4/registry`（multipart，`file=connect-ctf.tar`）
5. `GET /api/game/4/registry/connect-ctf` 取最新 tag，拼成 `<external>/<bucket>/connect-ctf:<tag>` 写回 `env.toml`

不想用脚本就点后台：**题目 → 环境 tab → 右上角「上传」**，选 `connect-ctf.tar`。同一个接口。

只想打包不传：`pwsh ./upload-image.ps1 -SkipUpload`。

### A3. 建题

`/games/4/challenges` → **创建题目**：

| 字段 | 值 |
|---|---|
| 名称 | `连接平台` |
| 标签 | `Misc`（主）+ `Web` |
| 初始分 / 最低分 / 衰减 | `50 / 50 / 1`（固定 50，不衰减） |
| 隐藏 | 赛前想藏就勾 |

进题目详情，逐 tab 填：

| tab | 内容 |
|---|---|
| 简介 | `题面.md` 全文 |
| Checker | `checker/main.rx` 全文（保存时平台会 lint，`check`/`environ` 缺一不可） |
| 环境 | 上传镜像后 → 添加镜像：仓库 `connect-ctf`、版本选最新时间戳、端口 `8080`、协议 `tcp` + `http`、CPU `0.2`、内存 `128Mi`、勾 **restricted**、出网关闭 |
| 提示 | `hints.toml` 里那条（cost 0） |
| 答案 | `answer.md` 全文 |

> 选完镜像，UI 会自动写 `<registry.external>/<game.bucket>/connect-ctf:<tag>`，
> 和 `env.toml` 里的 `tag` 字段是同一个字符串。

## 路线 B：git 题库仓库直推（批量时更爽）

题库仓库就是游戏的 bucket（裸 git repo）。后台「Git」tab 能拿到地址与凭据，然后：

```bash
git clone http://<token>@10.24.10.232/git/<bucket> game-repo
cd game-repo && mkdir -p challenges/connect-ctf/checker
cp /path/to/connect-ctf/{config.toml,env.toml,hints.toml,answer.md} challenges/connect-ctf/
cp /path/to/connect-ctf/题面.md challenges/connect-ctf/README.md
cp /path/to/connect-ctf/checker/main.rx challenges/connect-ctf/checker/
git add -A && git commit -m "add connect-ctf" && git push
```

push 时 post-receive 会同步并把日志直接回显给你：

| 文件 | 同步成什么 |
|---|---|
| `config.toml` | 题名、标签、计分规则、前置题（按 bucket 名引用） |
| `README.md` | 题面正文 |
| `hints.toml` | 提示（**只增不改**，改旧条目会被拒） |
| `env.toml` | 环境配置（校验端口不重复） |
| `checker/main.rx` | 会被 lint，有诊断会 warn 但不会中断 |
| `answer.md` | 题解 |

新增目录 = 新建题目；删目录 = 删题目。

⚠️ `env.toml` 的 `tag` 必须是 registry 里真实存在的 `<external>/<bucket>/connect-ctf:<时间戳>`，
否则启动环境时 Pod 会 `ImagePullBackOff`。

## 两个关键细节（都是踩过才知道的）

### 1. 镜像必须叫 `connect-ctf.tar`

仓库名 = 文件名第一个 `.` 之前的部分（服务端 `to_image_name(name.split('.').next())`，还会去掉
`\ / : * ? " < > |` 和空格并转小写）。所以 `connect-ctf-web.tar` → 仓库 `connect-ctf-web`，
`v1.0.connect-ctf.tar` → 仓库 `v1`。

### 2. 容器必须监听 8080，不是 80

平台起题目容器时默认 `restricted`：丢掉 `CAP_NET_BIND_SERVICE`。此时**连 root 都绑不了 80**，
Apache 直接起不来（现象：Pod Running 但端口拒连，日志 `Permission denied: AH00072: make_sock`）。
我们已把镜像改成监听 8080，`EXPOSE 8080`，`env.toml` 的 `port = 8080`。

本地已按平台的姿势验证过：

```powershell
docker run --cap-drop NET_BIND_SERVICE -e FLAG='flag{ok}' -p 8093:8080 connect-ctf-web:latest
# → 200，页面显示 flag{ok}
```

## 上传链路已实测（本地等价复现）

用和服务端完全相同的命令跑通了：

```bash
# 本地起一个 registry:2 顶替平台仓库
docker run -d --name r2s-reg -p 5005:5000 registry:2
# 服务端 registry.rs 里就是这么调的
skopeo copy --dest-tls-verify=false \
  docker-archive:/work/connect-ctf.tar \
  docker://r2s-reg:5000/test/connect-ctf:1750000000
```

结果：

```
{"repositories":["test/connect-ctf"]}
{"name":"test/connect-ctf","tags":["1750000000"]}
```

再把镜像从 registry 拉回来跑：`docker pull 127.0.0.1:5005/test/connect-ctf:1750000000` → 运行 → 页面 200，
显示的正是注入的 `FLAG`。也就是说 **tar 格式、skopeo 调用、镜像可拉可跑** 三项都验过了，
剩下只差用有权限的 token 打到平台上。

## 建完题的自测清单

1. 自己「启动环境」→ Pod Running
2. 用平台给的隧道地址（wsrx）打开 → 页面中间是 `flag{...}`
3. 提交 → 判对
4. 提交 `flag{00000000-0000-0000-0000-000000000000}` → 判错
5. 换个账号/队伍再启动 → **flag 应该不同**（`audit::encode_uuid` 按队伍 id 生成）
6. 后台看该题 `Instances`，确认 Pod 的 label `ret.sh.cn/internet=false`、镜像 digest 是刚上传的那条

## 常见坑对照表

| 现象 | 原因 |
|---|---|
| 上传报 `only support tar/tar.gz/tgz/tar.zst files` | 文件名后缀不对 |
| 仓库名不是你想要的 | 文件名里还有别的点，或含非法字符被替换/小写化 |
| 启动环境 `ImagePullBackOff` | `env.toml` 的 `tag` 不是 registry 里真实存在的链接 |
| Pod 起了但连不上端口 | 容器监听 80 而平台丢了 NET_BIND_SERVICE（本题已改 8080） |
| 页面能开但没有 flag | checker 的 `environ` 没返回 `FLAG`；页面会退回随机 flag，看起来"正常" |
| 起环境报 `at least one service with its exposed port is required` | `env.toml` 里没填 `port` |
| 提交通不过但 flag 是从页面上复制的 | flag 前后带空格/换行，或被 `htmlspecialchars` 转义过（本题不会） |
| 保存 checker 报 lint 错 | Rune 语法错，或缺 `check`/`environ` 之一 |
| 平台返回 `please login first` | token 过期或没带 `Authorization: Bearer` |
