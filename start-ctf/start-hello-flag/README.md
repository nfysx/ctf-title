# 先读懂规则

## 一、题目与考点

| 项 | 值 |
|---|---|
| 考点 | flag 格式规范、大小写与全半角、提交前的自检习惯 |
| 难度 | 1 / 5 |
| 附件 | `files/hello.txt` |
| Flag | `flag{you_read_the_rules_before_playing}` |

## 题面（直接复制到平台「简介」）

赛前须知里写了 flag 的书写规则，下面列了六条候选。平台做的是**逐字节比较**，多一个空格、错一个大小写、用了全角括号，都算错而且不会告诉你错在哪。

**任务**：找出唯一符合规则的那一条，原样提交。

**提示**：别急着猜哪条看起来最像答案，先拿规则一条一条去筛，把违反规则的逐条划掉。
## 三、解题步骤

### Step 1｜逐条对照规则

规则有四条约束：**前缀全小写**、**`flag` 与 `{` 之间不能有空格**、**花括号必须是半角**、**括号内只允许小写字母数字下划线且首尾无空格**。

拿这四条去筛六条候选：

| 候选 | 违反的规则 |
|---|---|
| `FLAG{case_does_not_match}` | 前缀大写 |
| `flag {space_before_brace}` | `flag` 与 `{` 之间有空格 |
| `flag（full_width_brace）` | 用了全角括号 `（）` |
| `flag{trailing_space_inside }` | 括号内尾部有空格 |
| `flag{has-hyphen}` | 括号内有连字符 `-` |
| `flag{you_read_the_rules_before_playing}` | 无 |

### Step 2｜复制时别多带东西

终端里选中复制常常会把行尾换行或缩进一起带走。提交前用一条命令确认：

```bash
echo -n 'flag{you_read_the_rules_before_playing}' | xxd | tail -2
```

输出的最后一个字节应该是 `7d`（`}`），而不是 `0a`（换行）或 `20`（空格）。

## 四、原理

平台判题脚本通常就是一行字符串比较（本题的 `checker/main.rx` 里就是 `submission.content == FLAG`）。
它不做任何归一化：不 trim、不忽略大小写、不做全半角转换。所以"看起来一样"和"字节一样"是两件事。

## 五、防御建议

自己写判题时，如果希望容忍手滑，可以在比较前做规范化（`trim()`、全角转半角），
但**必须同时把规范化规则写进题面**，否则选手会照着"看起来对"去提交然后被拒。
反过来，出题人自测时应该故意提交几个"差一个空格"的变体，确认它们真的被判错。
