## 题面（直接复制到平台「简介」）

某网关把同一条消息分别发给了两个下游，两边各用一把公钥，模数却相同，也都没有填充。附件给了 `n`、`e1 = 65537`、`e2 = 17` 和两条密文。还原那条消息。

**提示**：两条密文描述的是同一个明文，只是幂次不同；两个指数之间的最大公约数值得看一眼。

## 三、解题步骤

两个知识点叠加：RSA 公式 + 扩展欧几里得求 Bezout 系数。

```python
def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

g, a, b = egcd(e1, e2)                 # a*e1 + b*e2 = gcd(e1,e2) = 1
m = (pow(c1, a, n) * pow(c2, b, n)) % n   # a 或 b 为负时先取模逆
```

指数为负时用 `pow(x, -1, n)` 求模逆再取正幂（`exp/solve.py` 里的 `spow` 就是干这个的）。

## 四、原理

两条密文来自同一个 `m`：

```
c1 = m^e1 mod n
c2 = m^e2 mod n
```

因为 `gcd(e1, e2) = 1`，扩展欧几里得能给出整数 `(a, b)` 使 `a·e1 + b·e2 = 1`。
把两个密文按这两个指数做幂、再相乘：

```
c1^a · c2^b = m^(a·e1) · m^(b·e2) = m^(a·e1 + b·e2) = m^1 = m  (mod n)
```

私钥 `d` 从头到尾没被用到，也不需要分解 `n`。攻击成立的条件只有三条：
模数相同、指数互素、明文相同且无随机化填充。任意一条不满足（例如 OAEP 让两次加密的 `m` 不同）就打不动。

`e2 = 17` 是刻意选的：`gcd(65537, 17) = 1`，且 17 次幂远大于 `n`，
所以不能像 `e = 3` 那样直接开方绕过共模攻击。

## 五、防御建议

- 每次加密都用不同模数（即不同密钥对），绝不复用 `n` 给多个用户。
- 加密必须带随机填充（RSA-OAEP），让同一明文的两次加密结果无关，共模攻击的前提消失。
- 一对一密钥管理：一个私钥对应一个公钥指数、一套生命周期。
- 定期审计「同一 `n` 出现在多少个证书/公钥里」，这是历史上真实出现过的重大事故。
